# `src/adapters/` — host-framework adapters

Cross-cutting rules — the protocol revision, no runtime dependencies, commands, the package layout — are in the root `CLAUDE.md`; the layering of `src/` and the hot-path conventions are in `src/CLAUDE.md`. A rule lives in ONE file: add to the file of the folder it is about.

`src/adapters/` — host-framework adapters, each behind its own subpath: `mirror.js` (fastify route mirroring via `fastify.inject` — reverse-REST naming, JSON-Schema→`signature` distillation), `common.js` (shared plumbing that turns a framework request into the abstract `{ method, url, headers, body, respond }` call: `receiveBody`, `normalizeBody`, `statusLine`, `eachHeader`, `MAX_BODY_SIZE`), `uws.js` (`createUwsEngine`/`UwsSocket` — a standalone engine over uWebSockets.js), `fastify.js` (`wrpcFastify` plugin, node or uws backend by feature detection; `findUwsApp`), `express.js` (`createWrpc` → `{ rpc, engine, wsServer, handler, upgrade, close }` middleware that owns no listener). Node-only, never bundled for the browser. **Frameworks are injected, never depended on** — see "No runtime dependencies" in the root `CLAUDE.md`: `uWebSockets.js`, `fastify`, `fastify-uws` and `express` are devDependencies of the adapter tests and never a runtime dependency of any kind.

Closing is one function for every host: `shutdown` in `src/adapters/common.js` (the engine first, then the core, with the `drain` window) — `Server`, the fastify plugin and `createWrpc().close({ drain })` all go through it. The fastify plugin finds its backend structurally (a uws app first, else any server with `on`/`listen` — an `https.Server` is not an `http.Server`). In the mirror, the application's `mirror.headers` win over the caller's, a caller's header passes only by `mirror.allowHeaders`, and a path parameter of `''`, `.` or `..` is a 400 (`injectedHeaders` and `buildUrl` in `src/adapters/mirror.js`).

One mutation is on purpose: a native fastify route copies a handler's numeric `code` onto its own error's `statusCode` when that is unset (`wrpcFastify` in `src/adapters/fastify.js`). Under `restErrors: 'app'` the application's error handler must receive the application's own error — its class, its fields — and fastify reads the status from `statusCode`; a wrapper would hide both. wRPC's own refusals pass `statusCode` to the `WrpcError` constructor instead.
