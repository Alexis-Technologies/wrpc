# `src/` — the layers, and the files of the root

Every subsystem's folder has a `CLAUDE.md` of its own (the table is in the root one). This file holds what is true of all of `src/`, and the files that sit in `src/` itself. A rule lives in ONE file.

## Layers

- `src/rpc/` is the engine-agnostic server core: it never requires `src/websocket/`, `src/webrtc/` or `src/broker/`. Engines, adapters and bindings stand on its seams (`attachSocket`, `attachPort`, `attach`, `handleHttpCall`), never the reverse.
- Nothing under `src/` requires a framework, a broker client or an SDK: every host is injected and checked structurally (duck typing, never `instanceof` against an imported class).
- **Browser-reachable files are on a byte budget, and manual loops cost source bytes.** `src/client/*`, `src/utils.js`, `src/streams.js`, `src/sse/client.js`, `src/query/*`, `src/chunks.browser.js` and — through the wt client transport, which is in the MAIN entry — `src/webtransport/{channel,framing,streams}.js` all land in an entry with a min+gzip budget (`src/webrtc/*` and, through `PeerHost`, `src/rpc/{router,dispatcher,client,rooms,subscriptions,errors,serverTransport,meta}.js` land in the webrtc entry's) that `pnpm size` enforces in CI's lint job, and headroom is under 1 KB. The budgets themselves are `budget` in `scripts/size.js` — read them there, a number copied here goes stale. Optimize there only with a measurement that justifies the bytes; if the bytes are earned, raise the budget in `scripts/size.js` alongside the change, with a comment saying why — the ratchet's documented escape hatch. `src/websocket/*`, `src/rpc/*`, `src/adapters/*` and `src/transport.js` are Node-only and carry no budget. `src/deque.js` (the ring `Deque` every head-read queue uses) is Node-only too and must stay out of every browser entry.
- **Loops everywhere, and a hot-path hand-optimization cites its benchmark.** The conventions — what is hot, the `new Array(n)` a benchmark keeps, the loop a hot path's benchmark picks, why a `switch` is not turned into a table, which copies are load-bearing, the lint rules that shape a loop — are in `bench/CLAUDE.md`: read it before optimizing or restructuring anything that runs per frame, packet, chunk or recipient.
- A `catch` that does nothing says why in a comment inside it (`no-empty` with `allowEmptyCatch: false`); a queue is never read from its head with `Array#shift()` and a data array is never spread into a call — both are guarded site by site (`HEAD_READS` / `CALL_SPREADS` in `tests/package/consistency.test.js`).

## Platform pairs

Platform-specific code lives in matched pairs swapped via `package.json#browser`: `src/chunks.js`/`src/chunks.browser.js`, `src/runtime/node.js`/`src/runtime/browser.js`, `src/compression/native.js`/`src/compression/native.browser.js`, `src/encryption/aead.js`/`src/encryption/aead.browser.js`, `src/encryption/dh.js`/`src/encryption/dh.browser.js` and `src/encryption/hkdf.js`/`src/encryption/hkdf.browser.js` (`node:crypto` vs `crypto.subtle`), `src/client/ws-compression.js`/`src/client/ws-compression.browser.js` (the Node ws client's per-message compression; the browser half is a stub) and `src/client/ws-handshake.js`/`src/client/ws-handshake.browser.js` (how the declared bags leave on the ws handshake; here the BROWSER half is the larger one and the Node half requires it for its fallback). Add new pairs the same way if another Node-only API needs a browser equivalent.

## The files of `src/` itself

- `src/index.js` — the RPC-level barrel (client + server + streams + utils; websocket engine lives in the `./ws` subpath). `src/index.browser.js` — a slimmer barrel excluding server/transport (anything touching `node:http`/`node:https`).
- `src/server.js` — the batteries-included `Server` shell: `node:http(s)` + a WebSocket engine (default `createNodeEngine()`) composed around `RpcServer`. Constructor takes ONE options object with `router` — the old `(application, options)`/`getMethod` API is gone. With a **standalone** engine there is no node http server at all (`httpServer` is `null`), so always read the bound address through `server.address()`, never `server.httpServer.address()`.
- `src/transport.js` — `ServerTransport` and its http/ws/event subclasses; per-request CORS headers (`buildHeaders(cors, origin)`), cookies. `ServerHttpTransport` wraps an abstract `{ method, url, headers, body, respond }` call (net-free — the seam for framework adapters); `ServerWsTransport` is `(connection, meta)`.
- `src/wire.js` — the import-free wire-name constants (`wrpc_h`, `wrpc_meta`, `x-wrpc-meta`, `x-wrpc-meta-`, re-exported `x-wrpc-channel`, the revisions `WRPC_V1` `wrpc.v1` and `WRPC_V2` `wrpc.v2`, and the subprotocol CARRIER tokens `wrpc.h.`/`wrpc.m.`/`wrpc.bearer.` with the `CARRIER_PROTOCOL` pattern the negotiator — `negotiateProtocol` in `src/websocket/upgrade.js`, used by `src/websocket/server.js` and `src/adapters/uws.js` — filters out of the offer and refuses to echo), required by every module that speaks them; a spelling change is one file, not a multi-file grep. Also the framed-message kinds of a `0x00`-marked binary WebSocket frame (`FRAME_MARK`, `FRAME_PACKET_COMPRESSED` 3, `FRAME_CHUNK_COMPRESSED` 4 — a Node ws client's per-message compression, negotiated on ping/pong — the ping's `enc` is the client's id list, the pong's the ONE id to send with — and inflated in `RpcServer.attachSocket`; kinds 1–2 reserved).
- `src/attachments.js` — binary attachments: `hasBytes` (the per-packet walk every send pays once the feature is on; `attachments: false` skips it), `encodeAttachments`/`decodeAttachments` (the `0x00 01` frame — `u32 headerLen`, JSON `[packet, [[path, length], …]]` with `null` at each byte leaf, the buffers after; the decoder refuses forbidden keys, non-containers, non-null placeholders, depth > 32 and length mismatches, and COPIES every buffer out of the frame — `SegmentQueue` hands over views). Browser-budgeted (the client's send path). Wired into `ServerTransport.send`, `Client.sendEvent`, `Broadcast.emit` (one BINARY prepared frame per fan-out; the backplane half is refused), the HTTP batch/REST paths, `handleMessage`/`handleBinary` (a frame is a packet), the client's `send`/batch/`message` paths, and refused on SSE.
- `src/chunks.js` / `src/chunks.browser.js` — binary chunk framing (Node `Buffer` vs `TextEncoder`/`TextDecoder`), swapped via `package.json#browser`.
- `src/runtime/node.js` / `src/runtime/browser.js` — the one platform split needed beyond chunks: `generateUUID` (`node:crypto` vs `globalThis.crypto`), swapped via `package.json#browser`.
- `src/utils.js` — cross-platform primitives ported from `metautil` (`Emitter`, `jsonParse`; root `CLAUDE.md`, "No runtime dependencies"). `Emitter`, not `node:events`, for both platforms: `emit` settles once every listener has; `void emit` only where wRPC owns the listeners, else a `.catch` (`announce` in `src/streams.js`).
- `src/errors.js` — the classes every entry throws; `WrpcError` sets `details`/`expose`/`statusCode` only when given (absent on the wire).
- `src/logging.js` — the structured logger writer (Console- and pino-shaped loggers normalized to one `child()`/level facade; the frozen writer table lives here).

## `src/streams.js`

`src/streams.js` — `WrpcReadable`/`WrpcWritable`: chunked binary stream classes shared by client and server (browser-budgeted). The readable holds its sender to the announced `size`: `push` drops a chunk for a stream that is over and rejects for the one that goes past the size, `end` (the sender's end — what the dispatcher and the client call, not `close`) rejects short of it, and `fail` is the end a reader SEES — its iteration throws `error` — where `terminate` is the quiet one. `close` resolves once the reader has all of it: an empty stream once it has a reader at all, a failed one once a reader came to be told, which is what keeps both in a host's map until then. A feeder must therefore push a chunk in the turn it arrived in (`#handleBinary` in `src/client/core.js`), or the `end` behind it finds the stream short.

The bytes a connection may hold in streams nobody reads yet are the server's to cap: `heldBytes` in `src/streams.js` against `maxStreamBuffer`, summed on demand — one function for every feeder of readables. A readable's queue is read through a head cursor (`pull` in `src/streams.js`), never `shift()`: how long it gets is the sender's choice, and `shift()` made reading it back quadratic (`bench/stream-queue.js`); `queue` is a snapshot, `queued` the count.

A stream that is cut short FAILS for its reader — the sender's `terminate` (499) and a closed connection (503) throw from its iteration; only the reader's own `terminate()` is quiet — and one nobody reads is swept: `sweepStreams` in `src/streams.js`, armed per connection by `watchStreams` in `src/rpc/client.js` and by the client, fails what has had no reader and no byte for `streamIdleTimeout` (408) and reads it, which is what lets the `end` parked on it forget the stream.

The rule that admits a chunk under `maxStreamBuffer` is `overCap` in `src/streams.js`, one for both ends: a chunk counts as its bytes plus `CHUNK_COST`, a stream that has a reader is not counted where the carrier can pause (`paced` on the server-side `Client`, set in `attachSocket` from the engine's own socket) and is counted where it cannot — uWebSockets.js, whatever `attach` binds, and every client (`bench/stream-buffer.js`). The stream defaults (`MAX_STREAMS`, `MAX_STREAM_BUFFER`, `STREAM_IDLE_TIMEOUT`) live in `src/streams.js` for the server and the client alike; a limit an option sets goes through `checkLimit` in `src/utils.js`.

A stream's name is the SENDER's text: a message carries `shown(name)` (64 characters, nothing that starts a line), and a peer that breaks the stream protocol is one `stream.violation` warning per connection (`violation` in `src/rpc/dispatcher.js`), the rest at debug. Behind a worker, `WrpcClientProxy` tracks the pages that HOLD each server stream (`#downloads` in `src/client/proxy.js`) and tells the server once none is left. `writeAll` is the writable's paced "all of these bytes".
