# `src/broker/` — the message-broker family

Cross-cutting rules — the protocol revision, no runtime dependencies, commands, the package layout — are in the root `CLAUDE.md`; the layering of `src/` and the hot-path conventions are in `src/CLAUDE.md`. A rule lives in ONE file: add to the file of the folder it is about.

`src/broker/` — the message-broker family behind `@alexify/wrpc/broker` (experimental), Node-only. A broker is `{ name, backplane?, log?, queue?, direct?, close() }`; `port.js` holds the capability contracts in prose (their executable form is `tests/broker/{backplane,log,queue,direct}-contract.js`) and the structural checks, `memory.js` (`MemoryBroker`, the reference implementation of all four, microtask delivery, `trim`), `tail.js` (`TopicTails`: one shared live reader per topic, catch-up joined through `covered`/`advance` cursors — a Kafka cursor is a partition-offset vector, so the yielded id is the ADVANCED cursor), `ids.js` (`encodeToken` for broker alphabets, `signId`/`openId` for peer-supplied event ids, body/header normalization into null-prototype maps), `retry.js` (the ack/retry/release/dead table, `retryOn: [408, 429, 500, 503]`), `adapter.js` (the leaf the four adapters share: the `x-wrpc-attempt`/`-redelivered`/`-dead-reason` and `wrpc-text` header names, `idFactory`, `failedRead`/`guardedRead` for a `log.read` that is refused or position-checked, `checkConsume`/`checkListen`, `runDelivery` — deliberately NOT a shared delivery object: settlement is where the brokers differ).

Delivery settlement is `ack()/retry({delay})/release()/deadLetter(reason)` with an ADAPTER-owned attempt counter (`x-wrpc-attempt`): RabbitMQ 4 does not count a requeue. `src/rpc/` never requires `src/broker/`; the bindings stand on `RpcServer.attach(transport, { session | request | persistent: false })`, the `'draining'`/`'close'` events, `RpcServer#limits` and the telemetry writer's `withMessagingSpan`/`recordBroker*` (`src/telemetry/server.js` is bundled into the webrtc browser entry through `PeerHost`, so its bytes count there).

The scenarios on top: `feed.js` (`brokerFeed` — a subscription handler over a log, resume tokens signed with `secret`, `onGap` snapshots), `consumers.js` (`attachConsumers` — one long-lived client per binding attached with `persistent: false`, every delivery dispatched through `handleRpc` against a ONE-PROCEDURE ROUTER VIEW, so the dispatcher itself needed no change), `publisher.js` (`createPublisher` — `emits` checked by name, PRODUCER span, the trace context under the W3C header names `traceparent`/`tracestate`, renamed from the packet fields `tp`/`ts` the injector writes — a consumer that is not wrpc reads the W3C names; `consumers.js` reads `traceparent`, falling back to `tp`), `rpc/` (`attachBrokerRpc` + the `broker` client transport: stateless requests go through `handleHttpCall`, sessions through `attach` with per-direction frame numbers; `rpc/frames.js` is the one place a frame is read — `frameBody`, the `wrpc-enc` rule — and built — `sessionFrame`: kind, seq, compress-if-smaller, seal — for BOTH ends).

`src/broker/sealing.js` — sealed broker messages (Node-only): `createBrokerSealing(option, name, { layer, replay, text })` over the keyring envelope sealer of `src/encryption/envelope.js` with `echo: true` (a service may consume what it published). The HEADERS move inside with the body — `sealed(u32 hLen ‖ JSON(headers) ‖ body)`, opened back into a null-prototype STRING map — so a client's `authorization`/`x-wrpc-meta` no longer rest in the broker; the outer message keeps `wrpc-sealed: <kid>` plus what a carrier routes by.

RPC (`rpc/frames.js` `sealFrame`/`openFrame`, layer `'broker-rpc'`, replay window ON): context = `address\0kind\0correlationId\0seq`, `wrpc-kind`/`wrpc-seq` stay outer and are re-attached from the OUTER message after opening (an inner header can never forge them); both `attachBrokerRpc` and `ClientBrokerTransport` (`static encrypts = 'keys'` — the client option is the KEYRING form here, which `WrpcClient.#checkEncryption` lets through only for such a transport) seal every send and open every receive; a sealed `hello`/`request` is what passes `encrypted: true` to `rpc.attach`/`handleHttpCall`.

Events (`publisher.js`, `feed.js`, `consumers.js`, layer `'broker-log'`, replay OFF — a log is re-read, a delivery redelivered): context = the topic/queue, `text: true` base64 because the log/queue contracts only promise a STRING survives (a Redis stream field); a feed skips what does not open (`feed.refused`), a consumer dead-letters it with 400 (`broker.refused`); `sealing` is passed INTO `bindConsumer` — the delivery handler is not in `attachConsumers`' scope.

`src/broker/{redis,nats,amqp,kafka}/` — the adapters, one subpath each (`@alexify/wrpc/broker/<name>`), every client INJECTED and duck-typed. Redis: pub/sub + Streams (`XREADGROUP`/`XAUTOCLAIM`, a ZSET for delayed retries), lists for RPC groups. NATS: core subjects + JetStream (`headers()` is a package export, so it is injected separately; without the JetStream factories the broker has backplane + direct only). AMQP: a direct exchange, stream queues (`x-stream-offset`), quorum queues with a TTL retry queue, a fanout exchange per RPC address (RabbitMQ 4: a requeue does not count an attempt, and a transient non-exclusive queue kills the CONNECTION). Kafka: `shape.js` normalizes kafkajs vs `@confluentinc/kafka-javascript` (config nesting, the throwing `events` getter, metadata shape, the join signal); feeds are single-partition by default and seek to a pre-join watermark; NO `direct`.

`adapter.js` also holds what the four adapters would otherwise each spell: `attemptOf` (the attempt counter read from `x-wrpc-attempt` as an integer ≥ 1 — a producer cannot set it: `producerHeaders` strips the adapter-owned headers from a public `produce`), `sleep`, `reporter`, the `SETTLE_ATTEMPTS`/`SETTLE_BACKOFF` schedule, `refusalLevels`. A name becomes a broker token through `tokenEncoder` in `src/broker/ids.js` (a memo of 1,024 names over `encodeToken`; `bench/broker-token.js`). A head-read queue is the `Deque` of `src/deque.js` (`TopicTails`, the Redis and Kafka readers, `MemoryBroker`). On the RPC binding the reply address of a sealed `request`/`hello` rides INSIDE the seal (`HEADER_REPLY` in `src/broker/rpc/frames.js`) and a mismatch with the carrier's is refused (`encryption.reply: 'carrier'` opts out for a broker that rewrites it); a session frame takes its number only once it is built. `attachConsumers` takes `timeout` (a delivery's deadline, off by default) and `stallAfter` (how long every prefetch slot may stay busy before `healthy()` says no).
