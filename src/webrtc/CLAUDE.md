# `src/webrtc/` — peer-to-peer over data channels

Cross-cutting rules — the protocol revision, no runtime dependencies, commands, the package layout — are in the root `CLAUDE.md`; the layering of `src/` and the hot-path conventions are in `src/CLAUDE.md`. A rule lives in ONE file: add to the file of the folder it is about.

`src/webrtc/` — peer-to-peer wrpc over WebRTC data channels, behind the `@alexify/wrpc/webrtc` subpath (the second with a `browser` condition). Browser-safe (bundled through `src/webrtc/browser.js`, the `browser` condition): `port.js` (wrpc's OWN W3C-shaped structural `RtcAdapter` contract — `isRtcAdapter`/`isRtcPeerConnection`/`isRtcDataChannel`, `createW3cAdapter` over any `RTCPeerConnection` constructor; the core binds to NO Node WebRTC package), `framing.js` (the one-byte header + fragmentation to the negotiated message size; `FrameEncoder` reuses a scratch buffer — `bench/rtc-framing.js`), `link.js` (`RtcLink`: one pc, perfect negotiation, two negotiated channels — one per client→host direction — ICE restart, redial; roles by id order: lower id = initiator/polite=false), `transport.js` (`ClientRtcTransport`, registered as `WrpcClient.transport.webrtc`, and `RtcPeerTransport`; both run over an `RtcLink` OR over a raw data channel the application owns — `link` vs `channel`, the client's `channel` may be a factory the reconnect cycle asks for the next one; over a link `close()` on EITHER half closes the LINK and `terminate()` is local and asks the link for an ICE restart, over a raw channel both close the channel), `host.js` (`PeerHost`: router + dispatcher + one `Client` per peer, `trust: 'link'` pseudo-sessions; composed from `src/rpc/` leaves, never `RpcServer`), `signaler.js` (the `Signaler`/`RosterSignaler` contract + `wrpcSignaler(client, { identity, generateId })`; it remembers peer addresses and drops signals not addressed to its id/instance), `peer.js` (`WrpcPeer`: the links, the signals, a peer held for its `accept()`, incarnations, the assertion layer; `connect()` from the higher id sends a `connect` knock so there is never an offer glare), `peer-link.js` (`PeerLink`: one connected peer, both directions, the redial/knock cycle — it and `Mesh` are handed a narrow PORT built by the peer over its private state, never the peer itself), `ids.js` (the require-free leaf: `isPeerId`, `MAX_ID_LENGTH`, the one `deferred()`), `mesh.js` (`Mesh`: host Clients kept in `mesh:<room>`, so broadcast/ask are one `Broadcast` fan-out; a member whose signaling dropped is `away`, its link kept), `assertions.js` (trust assertions — the JWS ES256 verifier over `crypto.subtle`, `sdpFingerprint`; a token binds a peer id to the DTLS fingerprint of the pc that sent the description, verified in `WrpcPeer` before the link sees it and before `accept()`; `PeerHost` `trust: 'assertion'` requires the claims).

Node-only, in `index.js` only: `assertion-issuer.js` (`createAssertionIssuer`/`generateAssertionKeys`, required by `signaling.js` for its `assert`/public `keys` methods — the browser bundle carries the verifier only), `signaling.js` (`createSignalingUnit`/`createSignalingHooks` — a router fragment relayed through `RpcServer.sendTo`; a peer's id is what the `identity` strategy answers — the signaling client id by default — kept in a per-unit registry; every roster member and signal carries the routable `address` and the signaler's `instance`, so the relay never resolves an app-level id on the hot path) and `attachChannel(server, channel, options)` — the `attachPort` of WebRTC, an `RtcPeerTransport` over a raw channel handed to `RpcServer.attach`.

Two support leaves exist for the browser bundle's sake: `src/status.js` (the frozen `STATUS_CODES` table, replacing `node:http` wherever only a status line was wanted) and `src/rpc/errors.js` (`publicErrorMessage`/`wireError`, re-exported by `src/transport.js`); `ServerTransport` itself lives in `src/rpc/server-transport.js`, re-exported by `src/transport.js`, so a browser peer host never drags the HTTP/WS subclasses in.

The signaling unit's lookups in flight are counted per connection as well as per unit (`MAX_LOOKUPS` in `src/webrtc/signaling.js`), so one client with stuck lookups cannot starve the others; a `PeerLink` with no `connectTimeout` uses the link's default (30 s), not zero.
