# `src/rpc/` — the engine-agnostic server core

Cross-cutting rules — the protocol revision, no runtime dependencies, commands, the package layout — are in the root `CLAUDE.md`; the layering of `src/` and the hot-path conventions are in `src/CLAUDE.md`. A rule lives in ONE file: add to the file of the folder it is about.

`src/rpc/` — the engine-agnostic server core (never imports `src/websocket/`; node built-ins are fine — `client.js` uses `node:http`'s STATUS_CODES): `router.js` (`defineRouter`/`procedure`, versions as `'unit.vN'` keys, input/output validators, timeout/queue, the reserved `on` key holding a unit's inbound event handlers and the declaration-only `emits` key describing outbound ones), `rest.js` (the declarative REST bridge split out of router: `normalizeHttp`, the `rest.version` strategy, the per-verb segment trie — all cold paths), `core.js` (`RpcServer` with `attachSocket`/`attachPort`/`attach`/`handleHttpCall`/`to`/`except`/`broadcast` — `attach` is the structural seam, any persistent transport announcing `'packet'`/`'chunk'` events, checked by `isInboundTransport` from `serverTransport.js`; the WebRTC `attachChannel` is built on it from `src/webrtc/index.js`, so `src/rpc/` never requires `src/webrtc/`), `client.js` (`Client`/`Context`, split out of core — core requires it, never the reverse), `meta.js` (the connection-metadata parser: `declaredData` over the `x-wrpc-meta` header, its per-key spelling, the already-decoded `wrpc.m.` offer and the `wrpc_meta` query — token transports receive its OUTPUT, never re-run it; Buffer-free, because it is bundled into the WebRTC browser entry), `handshake.js` (Node-only: the ws handshake's declared bags from every carrier — `carriedBags` base64url-decodes the `wrpc.h.`/`wrpc.m.` subprotocol offers under ONE `metaMaxBytes` budget, `sanitizeDeclared` is the one sanitizer + `RESERVED_DECLARED` deny list for the offer and the `wrpc_h` query, a carrier is chosen never merged, and `readDeclared`/the exported `readHandshake(req)` is the single read both `attachSocket` and a `verifyClient` gate go through), `dispatcher.js` (packet routing over a `Router`), `sessions.js` (`SessionManager`, structural `SessionStore`, `MemorySessionStore`, cookie building, the widened `TokenTransport` port `read({ headers, url, declared, meta })`), `rooms.js` (`RoomRegistry`, the immutable chainable `Broadcast`, and `RoomsBackplane` binding a room registry to an injected backplane — with subscribe retry, a `linger` window on emptied channels and a `healthy` getter), `cluster.js` (presence with digest+sync corrective flow, a `rooms` replication filter, `fetchClients` with a loud `maxFetch` cap, addressed commands, node-to-node asks, opt-in HMAC envelope auth via `cluster.secret`, `instanceOfClientId`). The SSE channel registry is a core BUILT-IN with an `sse: false` opt-out, not an injected port — `SseChannels` needs `addClient` and the session identity, both core-owned; the shared `x-wrpc-channel` string comes from `src/sse/constants.js`, never from `sse/server.js`.

`src/rpc/subscriptions.js` — the subscription primitives: `tracked(id, data)` (labels a value for resume), `createEventLog({ size })` (ring buffer whose `since(lastEventId)` returns what was missed or `null` for a real gap), and `runSubscription` (the generator pump: one `data` packet per yield, transport backpressure honoured, exactly one `end`). The push→pull `createEventStream` lives in `src/utils.js` because the client needs it too.

`src/rpc/dictionary.js` — `buildDictionary(router)`: a preset dictionary for the per-message codecs from the router's introspection (signature/schema field names, `unit/method` targets, `unit/event` names, the packet skeletons — least to most frequent, the front cut past 32 KiB, deterministic so a fleet agrees on the id). Node-free; exported from the main entry and the WebRTC browser barrel. `src/compression/dictionary.js` is the Node codec over it (`dictionaryCompressor`, zlib `dictionary`, id `deflate-raw+dict:<fnv>` from `dictionaryId` in `compression/index.js`, threshold 64 B).

Lines about what a PEER did are rate-limited where they are written: `levelFor` in `src/rpc/dispatcher.js` answers `warn` for the first of a kind on a host and `debug` for ten seconds after it, over `lineLevels` in `src/rpc/errors.js` — the one limiter the backplane envelope (`src/rpc/envelope.js`) and the broker binding share; `Cluster#loud` is its own (swept with the presence records). Peer text reaches a log line through `clip` in `src/rpc/errors.js`, which bounds it and turns control characters into spaces. A slot taken in `client.calls` / `client.subscriptions` is released on EVERY path out of `handleRpc` / `handleSubscribe` — the try starts where the slot is set — and `sanitizeMeta` never throws (a `meta` too deep to measure is dropped like one too large).
