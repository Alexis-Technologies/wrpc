# `src/compression/` — per-message compression

Cross-cutting rules — the protocol revision, no runtime dependencies, commands, the package layout — are in the root `CLAUDE.md`; the layering of `src/` and the hot-path conventions are in `src/CLAUDE.md`. A rule lives in ONE file: add to the file of the folder it is about.

`src/compression/` — per-message compression for the transports with nothing under them (WebTransport and WebRTC), and the seam the Node↔Node carriers share: `index.js` holds the structural `Compressor` contract (`isCompressor`: `id` + `encode(bytes)` + `decode(bytes, maxOutput)`, either may answer a promise), `normalizeCompression` (strict; off in every spelling of off; `codec` is a name, a `Compressor` or a **preference list** of them — a name the platform lacks is skipped in a list, refused alone; the result carries `codecs`/`ids` plus the head's `codec`/`id`/`threshold`), `negotiate(local, peerIds) -> { encode, decode } | null` — **a sender compresses with the first codec of ITS OWN list the peer announced**, so the two directions choose independently, no WebTransport or WebRTC frame names its codec (a broker-binding frame does: `wrpc-enc: <id>` on each `packet`/`chunk`/`response`, `frameBody` in `src/broker/rpc/frames.js`), and a peer's list is bounded (16) and only ever compared, never a key — and re-exports the `Sequencer` that keeps messages in order around an asynchronous codec (synchronous fast path when nothing is in flight — `bench/message-compression.js`; the class itself is the `src/sequencer.js` leaf, so the `./encryption` entry has the ordering without the negotiation);

`ids.js` is the leaf (`dictionaryId`, `DICTIONARY_ID_PREFIX`, `isPromise`) that `src/deflate/` requires INSTEAD of `index.js`, so the `./deflate` entry carries no negotiation;

`native.js` / `native.browser.js` are the platform codecs, named as `CompressionStream` names its formats (`'deflate-raw'` — what `true` means — `'brotli'`, `'zstd'`), swapped via `package.json#browser`: the Node half takes the MEASURED levels of `bench/algorithms.js` (deflate 3 — the knee, level 4 is slower and larger; Brotli quality 4 — zlib's own default, 11, is 33 ms on 27 KB; zstd 1 with the size pledged), detects zstd through the injectable `hasZstd(zlib)` (node:zlib has it since 22.15 / 23.8 and `engines` is `>=22`) and is synchronous BY MEASUREMENT (`bench/zlib-async.js`: zlib's threadpool hand-off costs ~20 µs a call, so it loses below ~256 KB on deflate and at every size on inflate), with `async: { threshold }` handing only encodes that large to the threadpool, and only on the carriers with a `Sequencer` (WT, RTC; `sync.js` refuses a codec that declares `async`); the browser half asks the `CompressionStream` constructor which formats it has and answers null for the rest;

`codecs.js` (Node-only, exported from the main entry) is `deflateCompressor`/`brotliCompressor`/`zstdCompressor` — a level, threshold and `async` per codec, the id naming the FORMAT never the level;

`sync.js` is the Node-only half for the Node↔Node carriers — `normalizeSyncCompression` (probes EVERY codec of the list; a promise-answering one is a `ConfigError`), `headerNegotiator` (the broker binding's comma-separated `wrpc-enc`, last header memoized because a stateless request names its list every time), `encodeIfSmaller`/`decodeOrNull` over one list entry, and `createEnvelopeCodec` for the STRING backplane (base64 under a `wrpc-enc:<id>:` marker; nothing is negotiated there, so it ENCODES with the head and DECODES any codec on the list, markers matched whole and longest first because an id may hold a colon — a change of codec is a rollout without a lost envelope; injected into `RoomsBackplane`/`Cluster` by the core so the browser-bundled `rooms.js` carries none of it).

The wire names are codec-neutral: `caps.enc` (WT capabilities, WebRTC description), `KIND_*_COMPRESSED`, `FLAG_COMPRESSED`, `FRAME_*_COMPRESSED`, `parser.compressed`. Browser-budgeted: it lands in the main entry through the wt client and in the webrtc entry through both channel halves.

HTTP and SSE compression live elsewhere, in `src/content-encoding.js` (Node-only): `encodings` is the SERVER's preference list of `Content-Encoding`s (`'gzip'` default, `'br'`, `'zstd'`, each with its knobs, or a custom `{ encoding, encode, createStream? }` whose `encode` may answer a promise), `pickEncoding` is one hand-rolled scan of the peer-controlled `Accept-Encoding` with a bit per encoder (2× the split-and-map spelling, `bench/http-compression.js`; q=0 refuses, `*` covers the unnamed, other weights are not ranked — nginx's reading), `encodedWriter` wraps the SSE writer around a per-event-flushed stream and SSE refuses a coding with no `createStream`; gzip stays the SSE recommendation (Brotli/zstd save nothing on small events and hold 570/930 KB per open response against 320). `permessage-deflate` has no algorithm to choose — RFC 7692 is the only extension a browser implements.
