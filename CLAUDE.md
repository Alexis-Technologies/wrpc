# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

wrpc (`@alexify/wrpc`) is a fast, low-overhead, zero-dependency, WebSocket-based RPC protocol for Node.js and browsers.

**Protocol architecture.** The wire protocol is JSON packets (`{ type: 'call' | 'callback' | 'event' | 'stream' | 'ping' | 'pong', ... }`) over WebSocket or HTTP, plus a small binary framing (`chunkEncode`/`chunkDecode`) for streamed uploads/downloads. It is documented in `docs/reference/protocol.md`, which is updated per phase and frozen at 1.0. Module layout under `src/`:

- `src/client.js` — `WrpcClient`/`WrpcClientProxy`: the RPC client (WS/HTTP/ServiceWorker-event transports, call scaffolding via `#scaffold`, reconnect with exponential backoff + full jitter, app-level `ping`/`pong` heartbeat, automatic re-`load()` of loaded units on `'reconnect'`), plus `connect` — a one-line alias of `WrpcClient.connect` that exists so the contract type has a natural home (`connect<Api>(url)`).
- `src/rpc/` — the engine-agnostic server core: `router.js` (`defineRouter`/`procedure`, versions as `'unit.ver'` keys, input/output validators, timeout/queue, and the reserved `on` key holding a unit's inbound event handlers), `core.js` (`RpcServer` with `attachSocket`/`attachPort`/`handleHttpCall`/`to`/`except`/`broadcast`, plus `Client`/`Context`), `dispatcher.js` (packet routing over a `Router`), `sessions.js` (`SessionManager`, structural `SessionStore`, `MemorySessionStore`, cookie building), `rooms.js` (`RoomRegistry`, the immutable chainable `Broadcast`, and `RoomsBackplane` binding a room registry to an injected backplane).
- `src/rpc/subscriptions.js` — the subscription primitives: `tracked(id, data)` (labels a value for resume), `createEventLog({ size })` (ring buffer whose `since(lastEventId)` returns what was missed or `null` for a real gap), and `runSubscription` (the generator pump: one `data` packet per yield, transport backpressure honoured, exactly one `end`). The push→pull `createEventStream` lives in `src/utils.js` because the client needs it too.
- `src/sse/` — Server-Sent Events as a full transport behind the `@alexify/wrpc/sse` subpath: `server.js` (`ServerSseTransport` + `SseChannels`, the channel registry with `retention` and `Last-Event-ID` replay) and `client.js` (browser-safe `fetch` transport + incremental `SseParser`, registered as `WrpcClient.transport.sse`). A channel is `GET {basePath}/events?channel=<id>` plus POSTs carrying `x-wrpc-channel`, both bound to ONE server-side `Client`. Text-only: binary streams are refused on it. The seam that makes it possible is the optional `call.stream({ status, headers })` on the abstract HTTP call, implemented by `nodeStream()` in `src/adapters/common.js` for every host that hands over a node `ServerResponse`.
- `src/scaling/` — the rooms backplane behind the `@alexify/wrpc/scaling` subpath: the structural contract (`publish(channel, message)` / `subscribe(channel, handler) -> unsubscribe` / `close()`, checked by `isBackplane`), `memory.js` (`MemoryBackplane`, in-process, microtask delivery) and `redis.js` (`createRedisAdapter({ pub, sub, prefix })`, ioredis-shaped, clients **injected** — see "No runtime dependencies"). Delivery is at-most-once by design.
- `src/server.js` — the batteries-included `Server` shell: `node:http(s)` + a WebSocket engine (default `createNodeEngine()`) composed around `RpcServer`. Constructor takes ONE options object with `router` — the old `(application, options)`/`getMethod` API is gone. With a **standalone** engine there is no node http server at all (`httpServer` is `null`), so always read the bound address through `server.address()`, never `server.httpServer.address()`.
- `src/engine/` — the replaceable server-side engine port (`WrpcSocket` contract + `createNodeEngine` + `isEngine`), published as the `@alexify/wrpc/engine` subpath; the shared contract test suite lives in `tests/engine/engineContract.js`. Two engine kinds satisfy the port: **hosted** (`standalone` falsy) attaches to a listener someone else owns — `attach({ server, ... })` — and MAY expose `handleUpgrade(req, socket, head)` on its source for manual driving; **standalone** (`standalone: true`, uWebSockets.js) owns the whole network stack including `node:http`, is attached with no server — `attach({ path, verifyClient, onHttpCall, ... })` — and must implement `listen({ host, port }) -> Promise<address>`.
- `src/adapters/` — host-framework adapters, each behind its own subpath: `common.js` (shared plumbing that turns a framework request into the abstract `{ method, url, headers, body, respond }` call: `receiveBody`, `normalizeBody`, `statusLine`, `eachHeader`, `MAX_BODY_SIZE`), `uws.js` (`createUwsEngine`/`UwsSocket` — a standalone engine over uWebSockets.js), `fastify.js` (`wrpcFastify` plugin, node or uws backend by feature detection; `findUwsApp`), `express.js` (`createWrpc` → `{ rpc, engine, wsServer, handler, upgrade, close }` middleware that owns no listener). Node-only, never bundled for the browser. **Frameworks are injected, never depended on** — see "No runtime dependencies" below.
- `src/transport.js` — `ServerTransport` and its http/ws/event subclasses; per-request CORS headers (`buildHeaders(cors, origin)`), cookies. `ServerHttpTransport` wraps an abstract `{ method, url, headers, body, respond }` call (net-free — the seam for framework adapters); `ServerWsTransport` is `(connection, meta)`.
- `src/streams.js` — `WrpcReadable`/`WrpcWritable`: chunked binary stream classes shared by client and server.
- `src/chunks.js` / `src/chunks.browser.js` — binary chunk framing (Node `Buffer` vs `TextEncoder`/`TextDecoder`), swapped via `package.json#browser`.
- `src/websocket/` — a from-scratch WebSocket server implementation (handshake, framing, `WebsocketServer`, `Connection`, `SegmentQueue` O(n) receive buffering in `segments.js`, RFC 7692 permessage-deflate in `permessageDeflate.js`) used by `src/transport.js`; Node-only, never bundled for the browser. Published as the `@alexify/wrpc/ws` subpath (root `ws.js` shim + hand-maintained `ws.d.ts`) — engine internals are NOT exported from the main barrel. `WebsocketServer`'s `server` option is optional: without it nothing is bound and upgrades are driven by hand through the public `handleUpgrade(req, socket, head)`, which is how middleware adapters hook a listener they do not own.
- `src/utils.js` — cross-platform primitives ported from `metautil` (`Emitter`, `jsonParse`) — see "No runtime dependencies" below.
- `src/query/index.js` — the TanStack Query bindings behind the `@alexify/wrpc/query` subpath: `createQueryUtils(client, { prefix, queryClient })` returning `queryKey`/`queryOptions`/`mutationOptions`/`subscriptionHandler`. Option **factories**, in the style of tRPC v11 — never hooks — so one file serves React/Solid/Svelte/Vue Query and query-core alike. It `require()`s **nothing** (that is what keeps it at ~1 KB min+gzip and browser-safe), takes the client and the `QueryClient` by injection with structural validation, and resolves `['unit','method']` paths *lazily* inside `queryFn` because `client.api` only exists after `load()` and is rebuilt on every reconnect. Path lookups use `Object.hasOwn` on both hops: a unit object is an `Emitter`, so `['chat','on']` would otherwise resolve to `Emitter.prototype.on`.
- `src/cli/types.js` — the `wrpc types <url> --out api.d.ts` codegen, behind the `bin/wrpc.js` shim. Consumes `system/introspect` and writes the same shape of contract interface a user would hand-write for `connect<Api>()`; the `signature` descriptor format it reads is specified in `docs/reference/protocol.md`. Everything beyond argv is injected (`main(argv, { log, error, fetch, write, version })`), so the whole command is testable in-process. **Nothing from the wire is interpolated verbatim**: names go through `quoteKey` (JSON escaping, downgraded to single quotes only when nothing needed escaping) and type names are matched against a closed allowlist, with a depth cap on nesting.
- `src/runtime/node.js` / `src/runtime/browser.js` — the one platform split needed beyond chunks: `generateUUID` (`node:crypto` vs `globalThis.crypto`), swapped via `package.json#browser`.
- `src/index.js` — the RPC-level barrel (client + server + streams + utils; websocket engine lives in the `./ws` subpath). `src/index.browser.js` — a slimmer barrel excluding server/transport (anything touching `node:http`/`node:https`).

**No runtime dependencies.** An earlier pass ported code structurally from `metarhia/metacom`, which depends on `metautil`. Rather than install `metautil` (breaking the zero-dependency guarantee), the handful of functions actually used (`Emitter`, `jsonParse`, `generateUUID`, plus a few single-file-use helpers like `parseCookies`/`parseHost`/`receiveBody`/`split`/`parseParams`/`isError`) were copied in directly and adapted. `package.json` has no `dependencies` field at all — keep it that way; anything reused from another package must be copied in, not installed.

This rule extends to the adapters: **`uWebSockets.js`, `fastify`, `fastify-uws` and `express` are devDependencies used only by the adapter tests, and must never become runtime dependencies (not even `peerDependencies`/`optionalDependencies`).** Every adapter takes its host by injection — `createUwsEngine({ uws: require('uWebSockets.js') })`, `wrpcFastify` receives the fastify instance from `register()`, `createWrpc()` returns middleware the app mounts — and validates that injection structurally (duck typing, e.g. `isEngine`, `isTemplatedApp`) rather than by `instanceof` against an imported class. Nothing under `src/` may `require()` a framework.

Package manager is **pnpm** (`packageManager: pnpm@10.34.5`). CommonJS throughout (`require`/`module.exports`), no build/transpile step — `src/` ships as-is (same philosophy as the sibling `@alexify/kerberos` project).

## Commands

```bash
pnpm test              # run all tests: node --test (recursive discovery over tests/)
node --test tests/smoke.test.js            # run a single test file
node --test --test-name-pattern="..."      # filter tests by name
node --test tests/adapters/*.test.js       # adapter suites (node --test takes files, not dirs)
pnpm test:types        # type-check tests/*.test-d.ts against index.d.ts via tsd
pnpm test:coverage     # c8 coverage over src/ (thresholds: 95% lines/statements, 90% branches, 95% functions)
pnpm test:perf         # 1 GiB stream memory guard (tests/perf/, non-.test.js so node --test skips it)
pnpm lint               # oxlint src tests scripts bench bin
pnpm format             # oxfmt src tests scripts bench bin (format:check for CI)
pnpm bench              # runs every script in bench/ (bench/run-all.js), not just bench.js
pnpm size                # bundle-size report (scripts/size.js), also run in CI's lint job; browser-reachable entries carry a min+gzip budget and exceeding one FAILS the run
pnpm docs:dev            # VitePress dev server for docs/ (docs:build / docs:preview too)
```

Linting/formatting is **oxlint/oxfmt** (`.oxlintrc.json`, `.oxfmtrc.json`; the `correctness` category is intentionally off, and `no-void` is intentionally not enabled — this codebase follows the Metarhia style of `return void fn()` for explicit fire-and-forget) — their native bindings require Node ≥20.19. CI (`.github/workflows/ci.yml`) runs three jobs: `lint` (Node 22 — lint, format:check, size), `test` (Node 22/24 matrix — test:coverage, test:types; bare `node --test` recursively discovers `tests/adapters/**` too, so the adapter suites run here rather than in a separate job), `docs` (Node 22 — docs:build). Lint/format deliberately target `src tests scripts bench` only, so `docs/` is not covered by them.

Style: 2-space indent, single quotes, semicolons, 120-char lines (see `.editorconfig`, `.oxfmtrc.json`).

## Package layout conventions

Mirrors the `@alexify/kerberos` entry-point pattern:

- `index.js` → `require('./src/index.js')` — the Node/default entry.
- `ws.js` → `require('./src/websocket/ws.js')` + `ws.d.ts` — the `./ws` subpath (WebSocket engine). New subpaths follow the same pattern: root shim + hand-written root `<name>.d.ts` + `exports` entry + `files` additions + `tests/<name>.test-d.ts`.
- `engine.js` → `require('./src/engine/index.js')` + `engine.d.ts` — the `./engine` subpath (engine port: `createNodeEngine`, `isEngine`, the `Engine`/`WrpcSocket` contracts).
- `uws.js` → `require('./src/adapters/uws.js')` + `uws.d.ts` — the `./uws` subpath (`createUwsEngine`, `UwsSocket`).
- `fastify.js` → `require('./src/adapters/fastify.js')` + `fastify.d.ts` — the `./fastify` subpath (`wrpcFastify`, `findUwsApp`).
- `express.js` → `require('./src/adapters/express.js')` + `express.d.ts` — the `./express` subpath (`createWrpc`).
- `scaling.js` → `require('./src/scaling/index.js')` + `scaling.d.ts` — the `./scaling` subpath (`MemoryBackplane`, `createRedisAdapter`, `isBackplane`).
- `sse.js` → `require('./src/sse/index.js')` + `sse.browser.js` → `require('./src/sse/client.js')` + `sse.d.ts` — the `./sse` subpath. The only subpath with a `browser` condition: a browser needs the client transport, never the channel registry.
- `query.js` → `require('./src/query/index.js')` + `query.d.ts` — the `./query` subpath (`createQueryUtils`). Browser-reachable but needs **no** `browser` condition: `src/query/` has no Node-specific code, so one file serves both. `scripts/size.js` bundles it with `platform: 'browser'` under a budget to keep that true.
- `bin/wrpc.js` → `require('./src/cli/types.js')` — the `wrpc` command (`package.json#bin`). A shim on purpose: the logic lives under `src/` so the c8 thresholds cover it. Needs the shebang, the executable bit, and `bin/` in both `files` and the lint/format targets.
- `browser.js` → `require('./src/index.browser.js')`; resolved via the `package.json#browser` field map and the `browser` condition in `exports`. Do not deduplicate the two files even once they look similar — the browser entry intentionally excludes server-only modules.
- `index.d.ts` — hand-maintained types (not generated), covering the full `src/index.js` surface.
- `src/index.js` — the full barrel; `src/index.browser.js` — the browser-safe subset (see above).
- Platform-specific code lives in matched pairs swapped via `package.json#browser`: `src/chunks.js`/`src/chunks.browser.js` and `src/runtime/node.js`/`src/runtime/browser.js`. Add new pairs the same way if another Node-only API needs a browser equivalent.

## Testing

Tests live in `tests/` (not `test/` — this differs from `kerberos`), run via Node's built-in `node --test` runner (bare `node --test`, which recursively discovers `**/*.test.js` under the cwd — no vitest/jest config; note that `node --test` accepts *files*, not directories, so a targeted run needs an explicit glob). Non-`.test.js` files under `tests/` are shared test helpers, not test files themselves: `tests/websocket/mockSocket.js`, `tests/websocket/protocolClient.js`, `tests/engine/engineContract.js` (the shared engine port contract, run against both a hosted and a standalone engine via `hostedHarness`/`standaloneHarness`), and the swap-test pair `tests/adapters/boots.js` (the five boots — `Server` over each engine, the fastify plugin over each backend, express middleware) + `tests/adapters/spec.js` (the one behavioral spec every boot must satisfy). The `#ws` subpath import (`package.json#imports`) lets tests require the websocket barrel without a relative path. Type tests use `tsd` (`tsd.directory: "tests"` in `package.json`): `tests/index.test-d.ts` plus one file per published subpath — `ws`, `engine`, `uws`, `fastify`, `express`, `scaling`, `sse`, `query` — and every new subpath must bring its own. **`tsd` type-checks with `@tsd/typescript` (5.9), not the repo's own `typescript` (7.x)**, so a type that relies on newer inference must be checked against both; `tests/cli/e2e.test.js` is the one place the repo's `tsc` runs, on the d.ts the CLI generated.

Adapter tests take their frameworks from devDependencies and skip (never fail) when one is missing — see the `optional()`/`requireUws()` helpers in `tests/adapters/boots.js`, so a machine without a working `uWebSockets.js` binary can still run the suite.

**Warning — a leaked uws engine hangs `node --test` forever.** A standalone engine holds a native listen socket; if a test fails an assertion before its cleanup line runs, the socket is never released and the whole run wedges instead of reporting a failure. Always register teardown with `t.after(...)` immediately after booting, never as a trailing `await close()` at the end of the test body. When running a suite that might hang, redirect output to a file and read it back with a kill guard — piping through `tail`/`head` buffers the output and shows nothing.

## Documentation site (`docs/`)

VitePress site deployed to Vercel (`vercel.json` pins the build command/output dir); `docs/` is never published to npm (the `files` field in `package.json` is an explicit allowlist that omits it). Currently a skeleton (`docs/.vitepress/config.mts`, a `theme/` extending `DefaultTheme`, `docs/index.md` home page, `docs/guide/getting-started.md`, and `docs/reference/protocol.md` — the wire-protocol reference, updated per phase and frozen at 1.0) — expand the nav/sidebar in `config.mts` as more guide/API pages are added, following the fuller structure in `kerberos/docs/.vitepress/config.mts` as a reference.
