# `tests/` — the suites

The commands are in the root `CLAUDE.md`. A rule lives in ONE file: what is about testing goes here.

Tests live in `tests/` (not `test/` — this differs from `kerberos`), run via Node's built-in `node --test` runner (bare `node --test`, which recursively discovers `**/*.test.js` under the cwd — no vitest/jest config; note that `node --test` accepts _files_, not directories, so a targeted run needs an explicit glob). Non-`.test.js` files under `tests/` are shared test helpers, not test files themselves: `tests/websocket/mock-socket.js`, `tests/websocket/protocol-client.js`, `tests/engine/engine-contract.js` (the shared engine port contract, run against both a hosted and a standalone engine via `hostedHarness`/`standaloneHarness`), and the client-transport contract `tests/client/transport-contract.js` (structural, run over ws/http/event/sse/webrtc in `tests/client/transports.test.js`), the WebTransport helpers `tests/wt/fake-web-transport.js` (`createFakeWt()` — one in-memory W3C-shaped session class for BOTH ends, with `hold()`/`uniQuota`/`cancel` hooks) and `tests/wt/channel-contract.js` (the channel's behavioural contract, run over `WtSocket` and `ClientWtTransport`), the WebRTC helpers `tests/webrtc/fake-rtc.js` (`createFakeRtc()` — an in-memory W3C-shaped implementation with `failIce()`/`blackhole()`/`restartIce()` hooks), `tests/webrtc/port-contract.js` (the shared `RtcAdapter` contract, run on the fake and, by hand, on node-datachannel), `tests/webrtc/raw-channel.js` (`rawChannelPair()` — two fake pcs with a negotiated channel each, offer/answer done by hand: the raw-channel level's own signaling) and `tests/webrtc/fake-signal-hub.js` (an in-memory `RosterSignaler` hub with `mute`/`drop`/`reset`), the broker contract suites `tests/broker/{backplane,log,queue,direct}-contract.js` plus `tests/broker/support.js` (each suite takes a harness whose `open()` returns the capability, an optional `peer` on the same broker and optional hooks like `trim`/`foreignId`, so one suite runs over memory, an in-repo fake and a real server), the ioredis-shaped fake `tests/scaling/fake-redis.js` (delivers on a microtask, never inside `publish()`), the four in-process brokers the adapter suites run on — `tests/broker/fake-redis-server.js` (Streams, groups, lists, blocking reads), `tests/broker/fake-nats.js` (core subjects + JetStream consumers with ack_wait/nak/term), `tests/broker/fake-amqp.js` (exchanges, quorum/stream queues, TTL + DLX, mandatory returns) and `tests/broker/fake-kafka.js` (partitions, groups, commits — in BOTH KafkaJS client shapes) — the interop peers `tests/interop/peers.js` (`next`/`legacy` — this tree and the published 1.0 — one `boot`/`connect` for either, and `browserBuild()`, which bundles the BROWSER client with esbuild and evaluates it in Node: the only way to drive a page's handshake carriers, since a Node client sends real headers), the shared server boot `tests/helpers/server.js` (`bootServer`/`connectClient` — the default for NEW server-driving suites; never read a bound port through `server.httpServer.address()`), the one `waitFor` of the suites in `tests/helpers/wait.js` (`waitFor(predicate, message | { message, timeout, interval })`, deadline-based, default 5 s or `WRPC_TEST_TIMEOUT`; `server.js`, `tests/broker/support.js` and `tests/webrtc/port-contract.js` re-export it — never write another copy, and prefer it to a fixed sleep before a POSITIVE assertion; a sleep is for "nothing more arrives", and the queue contract scales those windows by the harness's `settle`/`ackWindow`; its `keepAlive()` holds the event loop for a file whose tests await an unref'd close/idle timer over a fake — Node 22's runner cancels the rest of the file when the loop goes empty, Node 24's does not, so a local run on 24 never shows it), and the swap-test pair `tests/adapters/boots.js` (the five boots — `Server` over each engine, the fastify plugin over each backend, express middleware) + `tests/adapters/spec.js` (the one behavioral spec every boot must satisfy). The `#ws` subpath import (`package.json#imports`) lets tests require the websocket barrel without a relative path. Type tests use `tsd` (`tsd.directory: "tests"` in `package.json`): `tests/index.test-d.ts` plus one file per published subpath, the per-broker ones under `tests/broker/` — every new subpath must bring its own, and the guard `every published subpath has a tsd file` in `tests/package/consistency.test.js` is the list (do not copy it here). **`tsd` type-checks with `@tsd/typescript` (5.9), not the repo's own `typescript` (7.x)**, so a type that relies on newer inference must be checked against both — `pnpm check:dts` (`tsconfig.dts.json`, strict, node types) runs the repo's `tsc` over every hand-written d.ts, CI's lint job and `prepublishOnly` with it, and `tests/cli/e2e.test.js` runs it on the d.ts the CLI generated.

A suite is `describe` blocks named after what they test, each case an `it('should …')` — the title says what is expected and starts with `should` — asserted with `node:assert/strict`, as alexiskills asks (`node-tooling-testing`); `test()` and the loose `node:assert` are gone since 2.3. Array iteration methods are fine here. A strict assertion that fails on a prototype (`Object.create(null)` against `{}`) or a type (`Buffer` against `Uint8Array`) is fixed by comparing with a value of the right kind, never by loosening it. A contract suite registers its cases in the caller's `describe`, synchronously — `runBackplaneContract`/`runLogContract`/`runQueueContract`/`runDirectContract`/`runFeedSpec` take `(title, harness, options)`, `runRtcPortContract(harness, { skip })`, `runChannelContract(harness)`, `runEngineContract(harness)`, `runAdapterSpec(entry)`, `runTransportContract(name, Transport)` — and an integration suite hands its `{ skip }` to every `it`, never to the `describe`: a skipped `describe` lists none of its cases. Setup a `describe` shares goes into `before`/`after`, never its body; a `before` hook's context has no `after`, and node:test's own `after()` called inside a running hook fires when that hook ends, so `suiteScope()` in `tests/helpers/scope.js` is the `{ after }` to hand `bootServer`/`connectClient` there, closed by the `describe`'s `after`.

Adapter tests take their frameworks from devDependencies and skip (never fail) when one is missing — see the `optional()`/`requireUws()` helpers in `tests/adapters/boots.js`, so a machine without a working `uWebSockets.js` binary can still run the suite.

**Warning — a leaked uws engine hangs `node --test` forever.** A standalone engine holds a native listen socket; if a test fails an assertion before its cleanup line runs, the socket is never released and the whole run wedges instead of reporting a failure. Always register teardown with `t.after(...)` immediately after booting, never as a trailing `await close()` at the end of the test body. When running a suite that might hang, redirect output to a file and read it back with a kill guard — piping through `tail`/`head` buffers the output and shows nothing.

## The integration suites

`tests/scaling/redis.integration.test.js` covers the Redis backplane against a real server and runs in CI's `redis` job (a Redis service container); locally it is `REDIS_URL=redis://127.0.0.1:6379 node --test tests/scaling/redis.integration.test.js` — the in-repo ioredis-shaped fake in `tests/scaling/fake-redis.js` is what `pnpm test` actually exercises. `compose.yaml` also starts RabbitMQ, Kafka and NATS (+JetStream) for the broker integration suites (`pnpm brokers:up`); each `tests/broker/*.integration.test.js` skips without its env var (`REDIS_URL`, `NATS_URL`, `AMQP_URL`, `KAFKA_BROKERS`) and has a CI job of its own (`redis`, `nats`, `rabbitmq`, `kafka`). Every broker client is a devDependency used ONLY by those suites — `ioredis`, `@nats-io/transport-node` + `@nats-io/jetstream`, `amqplib`, `kafkajs` and `@confluentinc/kafka-javascript` (the last one is a native build, allow-listed in `pnpm-workspace.yaml`).

The WebRTC and WebTransport suites against a real implementation are manual, like Redis, and not in CI:

```bash
WRPC_RTC=node-datachannel node --test tests/webrtc/node-datachannel.integration.test.js   # WebRTC port contract against a real implementation (manual, like Redis)
WRPC_WT=fails node --test tests/wt/fails.integration.test.js   # WebTransport over @fails-components/webtransport (native binary) — manual, not in CI
WRPC_WT=quico node --test tests/wt/quico.integration.test.js   # …and over the pure-JS quico — manual, not in CI
```

## Which devDependency is whose

`package.json` has no `dependencies`, `peerDependencies` or `optionalDependencies` field (the rule is in the root `CLAUDE.md`); every entry of `devDependencies` is test-, bench- or docs-only. The same holds for the other injected or compared packages: `ioredis` (only `tests/scaling/redis.integration.test.js`, which is skip-guarded on `REDIS_URL`), `wrpc-v1` (the PUBLISHED 1.0 under an npm alias — `npm:@alexify/wrpc@1.0.0` — only `tests/interop/`, the other end of the revision-negotiation matrix) and `wrpc-v2` (the PUBLISHED 2.0.1, `npm:@alexify/wrpc@2.0.1`, only `tests/interop/` too — the older 2.x peer an additive field is asked of), `node-datachannel` (only `tests/webrtc/node-datachannel.integration.test.js`, skip-guarded on `WRPC_RTC`; the WebRTC port in `src/webrtc/port.js` is wrpc's own W3C-shaped structural contract and binds to NO Node implementation — `createW3cAdapter(require('node-datachannel/polyfill'))` is one injection among any), `@fails-components/webtransport` (+ its native `-transport-http3-quiche`) and `quico` (only `tests/wt/fails.integration.test.js` / `tests/wt/quico.integration.test.js`, skip-guarded on `WRPC_WT`), the broker clients (above), `@tanstack/query-core`, `pino`, `ws`, `@fastify/websocket` and the `@opentelemetry/*` packages (injected in tests only), `socket.io`/`socket.io-client`/`@trpc/server`/`@trpc/client`/`@grpc/grpc-js`/`@grpc/proto-loader` (only `bench/support/rpc-stacks.js` and `bench/support/http-servers.js`), and `autocannon` (only `bench/http-comparison.js`).
