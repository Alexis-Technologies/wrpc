# `docs/` — the documentation site

VitePress 1.x site deployed to Vercel (`vercel.json` pins the build command/output dir); `docs/` is never published to npm (the `files` field in `package.json` is an explicit allowlist that omits it). It is the **full site, not a skeleton**: `docs/index.md` (home), a `guide/` track (introduction → server → client → transports & hosts → operations, plus `guide/adapters/`) and a `reference/` track (`protocol.md` — the wire protocol at revision 2.0 — `wire-format.md`, `engine.md`, `errors.md`). Every page is reachable from the sidebar in `docs/.vitepress/config.mts`, so **a new page means a new sidebar entry in the same change** — an orphan page is invisible. Two things in that config are hand-synced with `package.json` and are release-checklist items: the `nav` version label and the `keywords` array.

The encryption story has ONE home, `docs/guide/encryption.md` (Operations group): the decision table, the primitives and what is left to injection, each layer, the costs, the limits. The scaling, sessions, security, production, codec and compression pages link INTO it and keep only what is theirs (the rollout table of `rooms.encryption` lives on the scaling page; `sealedStore` on the sessions page); wire formats are in `reference/protocol.md` (`#session-encryption`, `#sealed-requests`, `#broker-sealing`).

`pnpm docs:build` fails on dead links, which is what CI's `docs` job is for. Lint/format deliberately do not cover `docs/`.

**Benchmark charts are `<BenchChart set="…" />`** (`docs/.vitepress/theme/components/BenchChart.vue`, registered in `docs/.vitepress/theme/index.ts` BEFORE its SSR guard so the charts pre-render): horizontal bars, wRPC rows in the brand green and every other row gray, sorted best first, a metric switch, a hover/focus tooltip against the first wRPC row. No chart library. The numbers live in `docs/.vitepress/theme/benchmarks.json` and are a COPY of the table printed under each chart — re-running a benchmark means updating both, and a guard in `tests/package/consistency.test.js` refuses a charted number its page does not print (and a `<BenchChart>` naming a dataset or `pick` row that does not exist). The accent/gray pair was validated for contrast and colour-blind separation on both surfaces; keep it.

**Diagrams are mermaid**, through `vitepress-plugin-mermaid` (already wired: the config is wrapped in `withMermaid`). Write them as ` ```mermaid ` fences. Three constraints that are easy to rediscover the hard way: the config must **not** set `mermaid.theme` (the plugin picks `default`/`dark` from VitePress' `isDark` and re-renders on toggle; setting it freezes diagrams in one theme); mermaid's CJS-only transitive deps (`dayjs`) need `vite.optimizeDeps.include` or the dev server fails to boot; and `.mermaid` label `line-height` must be pinned to 1.25 in `custom.css` or multi-line labels overflow the shapes mermaid measured them into. Check a new diagram in **both** themes and at mobile width.

**Branding** lives in `docs/public/` (`logo-mark.svg` — the mark: a Node.js hexagon holding the two directions of an RPC — `favicon.png`, `logo.png` for `og:image`, `robots.txt`, `llms.txt`) and `docs/.vitepress/theme/custom.css` (Node.js green `#5FA04E` on ink `#1B1C1E`, applied by overriding VitePress CSS variables — the Pinia/Vite pattern, layout untouched). Light-theme `--vp-c-brand-1/-2` are **darkened** greens because `#5FA04E` fails WCAG AA as link text on white. The raster assets are generated from the mark by `node scripts/brand.js` (macOS `qlmanage`; re-run it after changing `logo-mark.svg`).

**Analytics** is Vercel Web Analytics + Speed Insights, wired in `docs/.vitepress/theme/index.ts` via `enhanceApp`. Both use the **framework-agnostic** `inject()`/`injectSpeedInsights()` entrypoints rather than the `@vercel/*/vue` components, because those declare a `vue-router` peer and VitePress ships its own router; the imports are dynamic and guarded by `import.meta.env.SSR` so nothing reaches the SSR pass of `docs:build`. Analytics picks up VitePress' pushState navigations by itself, Speed Insights does not — its `setRoute` is chained onto `router.onAfterRouteChange` (chained, not replaced). Both are devDependencies (docs-only, like `vitepress` itself — the zero-dependency guarantee is about `dependencies`), and data only flows once Web Analytics and Speed Insights are enabled on the Vercel project.

`docs/CLAUDE.md` itself is not a page: `srcExclude` in `docs/.vitepress/config.mts` keeps it out of the build, and the chart guard skips it.
